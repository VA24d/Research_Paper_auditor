Abstract

Reviewers rarely open the papers a submission cites or the code it releases, so a wrong citation or a setting that differs from the code usually goes unnoticed. We built an auditor that checks a paper (PDF or LaTeX) against the papers it cites and its code repository. It splits the paper into small items and sends each item to a specialist checker. It reports a problem only when it can quote the evidence and a verifier finds that quote in the source.

We compared it with two baselines on the same model. B0 (LLM) reads the paper once with no tools. B1 (Agent) is a single agent with the same tools but no verifier. The test set has 40 papers with their code. Each paper appears twice, as the original and as a copy with planted errors (80 paper versions, 163 labelled errors, 72 unchanged control items). Over three runs the full system scores a Macro-F1 of 0.636, against 0.048 for B0 (LLM) and 0.046 for B1 (Agent). No system flags any control item. The full system also costs about a seventh of B1 (Agent) ($0.079 against $0.542 per paper version). On its own, the citation checker scores an F1 of 0.879 on the HALLMARK reference benchmark.

How it works

1Read

GROBID parses the PDF into sentences, references, citations and tables. A planner turns them into small tasks: one per reference, citation, setting, method and claim.

2Check

Four checkers run in parallel. Citations: the reference exists and supports the sentence. Code and data: settings, metrics and methods match the repository. Theory: claims hold. Integrity: placeholders, impossible means, text against tables.

3Verify

The verifier looks for every quoted line again in its source. A finding whose quote is missing is dropped. One that rests on a record not being found goes to a person.

4Report

Each finding comes with its sentence or code lines and the quote. Verified flags, items for human review and checks that did not finish are listed apart. A person decides.

Limitations

  • Most labelled errors are planted. Only the 8 discrepancies reported by SciCoQA users are real, and they make 16 of the 163 labels.
  • All main runs use one model family (Gemini). B1 (Agent) has two runs, not three.
  • Method recall is low (F1 0.34). Most misses are code the model saw but did not report.
  • We have not checked the unlabelled flags on the original papers by hand, so we cannot yet say how many are real problems.
