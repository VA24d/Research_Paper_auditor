Why papers need this check

Conferences receive more papers than reviewers can read closely. ICLR 2026 received 19,525 submissions, and more than 62,000 abstracts were registered for ICLR 2027. A reviewer does not open every cited paper to see whether it says what the citing sentence claims, and does not compare each reported setting with the released code. Some errors that slip through are invented references, and language models make it easy to write one that looks right but is wrong. In January 2026, GPTZero, a company that detects AI-written text, listed 100 fabricated citations in 51 accepted NeurIPS 2025 papers (The Register).

An AI reviewer sees only the submission, so it cannot tell what a cited paper or the code says. Reference checkers only confirm that a reference exists. None of the systems we surveyed checks references, claim support, code and a paper's own numbers together, or holds back a finding it cannot back with a quote.

What the auditor does

The auditor takes a paper (PDF or LaTeX) and, optionally, its code repository. It splits the paper into small items, such as one reference, one claimed setting or one theorem, and sends each item to a specialist checker. A false accusation harms an author, so a finding is shown only when it carries a verbatim quote and a separate verifier step finds that quote again in its source. The report is advisory: a person confirms each finding.

1Read

A parser extracts the sentences, references, citations and tables. The paper is then split into small checks, such as one per reference or per claim.

2Check

Four checkers run in parallel. Citations: the reference exists and supports the sentence. Code and data: settings, metrics and methods match the repository. Theory: the proofs hold. Integrity: leftover template text, averages that whole-number data cannot produce at the stated sample size, and text that contradicts its own tables.

3Verify

The verifier looks for each quoted line in its source. A finding whose quote is missing is dropped. A finding that a reference is missing from public bibliographic databases (OpenAlex, Crossref) cannot be quoted, so it goes to a person.

4Report

Each finding comes with its sentence or code lines and the quote. The report lists three groups: verified flags, items for human review, and checks that did not finish.

Errors it flagged in real papers

Unlike our main tests, which use errors we inserted ourselves, each error below was already in a published paper. The sources are the news, a retraction, or SPOT, a public collection of errors found in published papers.

arXiv:2506.12241v2

“Zayne Sprague, Xi Ye, Kyle Richardson, and Greg Durrett. MuSR: Testing the limits of chain-of-thought with multistep soft reasoning. In EMNLP, 2023.”

Auditor: the cited paper is real, but the reference lists Kyle Richardson, who is not an author. The OpenAlex record names five authors: Sprague, Ye, Bostrom, Chaudhuri and Durrett. This was a verified flag.

Retracted preprint · SPOT
Every Polish group has a non-trivial topological group automorphism
arXiv:2408.16162v2, retracted.

What the paper says (proof of Theorem 1.1)

“we take any non-trivial automorphism φ of span{xi}i<n and extend it to a ℤ2-automorphism of H by setting φ(y) = y for y ∈ Y.”

What the auditor reported

The proof keeps a set Y fixed while moving other elements. The auditor gave a case, y1 + y2 + y3 = x1, where an element that must move is built from fixed ones. This is a counterexample, not a quote.

SPOT's annotation names the same cause: fixing Y can redefine the automorphism on elements that Y generates.

Retracted · SPOT · arXiv:2403.01085v2
A strongly subcubic combinatorial algorithm for triangle detection

Paper: if a triangle has a vertex next to the start vertex of the breadth-first search, the search always notices the triangle.

Auditor: a small graph (a counterexample) where an extra vertex lets the search reach the triangle by another route and miss it. SPOT records this step as the flaw behind the retraction.

In version 1 · arXiv:2312.11580v1
PlaNet-S: placenta segmentation

Paper, in the abstract and twice in the results: “PlaNet-S had significantly higher IoU (0.73 ± 0.13) than that of U-Net (0.78 ± 0.010).”

Auditor: the text says PlaNet-S is higher, but 0.73 is below 0.78.

How well it works

Our main test uses 40 papers that come with their code. Each paper appears twice, as published and as a copy in which settings, metrics or methods no longer match the code. This gives 163 labelled errors (147 inserted by us, 16 real mismatches from SciCoQA, a dataset of paper-and-code discrepancies reported by users) and 72 unchanged items that must not be flagged.

We compare four systems that use the same model. The full auditor is the system described above. “Without verifier” removes the verifier step. “One read” is the model reading the paper once with no tools. “Tool-using agent” is one agent with the same tools and no verifier. The score is F1, from 0 to 1, which balances the share of errors found against the share of flags that are correct.

  • Neither baseline finds a single method or metric error. The full auditor scores 13 times the one-read baseline.
  • The verifier trades a small drop in detection (F1 0.667 to 0.636) for fewer unsupported flags (391 to 255 per run) and a quote on every flag.

Limitations

  • Most test errors are inserted by us. Only 16 of the 163 labelled errors are real mismatches, taken from SciCoQA (8 mismatches, counted once per copy of a paper); the other 147 are inserted.
  • All main runs use one model family, Gemini.
  • The auditor finds about 37% of the labelled errors (overall F1 0.636). It is weakest on methods that differ from the code (F1 0.34); usually it saw the code and did not report the difference.
  • It also raises extra flags on original papers, many of them minor differences in reference details. We have not checked them by hand, so we cannot say how many are real problems.

Try it

Upload a paper as PDF or LaTeX and, if you have it, a link to its code. The app returns a list of flagged items, each with the quoted evidence and a status: verified, needs human review, or did not finish.
